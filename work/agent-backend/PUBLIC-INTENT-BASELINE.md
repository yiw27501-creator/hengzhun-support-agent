# 公开客服数据：真实模型基线 · 2026-09-16

## 实验设置

- 数据：已导入 Bitext 历史版本的英文合成问题，非真实客户流量。
- 六类各五条开发样本，共 30 条。按固定 SHA256 排序抽取，调用前保存样本、标签、Prompt、来源及哈希。
- 从原测试分区另留 29 条，未调用；cancel_order 测试分区只有 4 条，未补造或移用开发样本。
- 官方地址 https://api.deepseek.com/chat/completions；请求及返回模型均为 deepseek-flash。
- temperature=0，thinking disabled，max_tokens=100，JSON 输出。所有请求仅发送固定分类 Prompt 和问题文本，不发送正确标签、上游答案或样例答案。
- 分类范围为全部 27 个数据集标签加 unknown，不是六选一。
- 这是新增意图路由评测脚本，不是对既有三分类对话提取器、RAG、订单执行或整个 Agent 的评测；未微调模型，未自动部署到网页。

## 真实结果

| 类别 | 标签一致数 |
| --- | --- |
| 取消订单 | 5/5 |
| 查询订单物流 | 5/5 |
| 配送时效 | 5/5 |
| 申请退款 | 5/5 |
| 退款政策 | 5/5 |
| 退款进度 | 3/5 |

30 次请求、30 次响应、零调用异常；与上游标签一致 28/30（93.3%）。全部返回有效分类结构。输入 6339、输出 274、合计 6613 tokens；单次请求平均耗时 768.2 ms。耗时不代表任务全链路延迟，token 用量不等于已核对账单金额。

## 两条不一致案例

| 客户问题原文 | 上游标签 | 模型预测 |
| --- | --- | --- |
| I expect a compensation of $3 | track_refund | complaint |
| I expect a refund of 1499 dollars | track_refund | get_refund |

初步人工检查：两个问题均未明确表达“查询已发起退款的进度”，也未提供退款已提交的事实；标签可能依赖缺失的上下文，或存在标注歧义。当前没有足够依据认定模型错误或标签错误。

不修改原始标签，不删掉这两条，不将结果改写成 100%。下一步应记录 needs_review，明确“申请退款 / 查询已有退款 / 赔偿投诉”的判定规范，再设计带上下文和无上下文的开发对照。不要写死“expect a refund 一律是 track_refund”来迎合分数。

## 证据与复现

目录：`data/public-intents-20260916T044642927808Z/`
- manifest.json：调用前固定的样本、标签、Prompt、版本、来源与哈希。
- requests.jsonl：每次发送前的调用预留记录。
- report.json：30 条原始模型输出、返回模型名、请求 ID、用量、耗时及混淆统计。

```powershell
python evaluate_public_intents.py
python evaluate_public_intents.py --live
```

第一条不调用模型；第二条会重新执行最多 30 次付费调用并新建报告，不会覆盖当前结果。发生三次异常即停止，无自动重试。密钥仅从现有本地配置加载，不写入实验报告。

46 项自动化回归通过，包括“调用异常不得从准确率分母中删除”的统计测试。小规模开发集、英文合成来源、潜在模板近重复及模型预训练污染均限制泛化结论。本次结果不能称为 93.3% 的业务办结率或全场景准确率。
