# 衡准：数据、知识与质量运营规范 v1

状态：2026-09-16，本机合成场景。本文区分已实现接口与待实现需求，不是业务上线证明。

## 1. 范围和验收

目标用户：售后运营、知识维护者、AI 产品经理；本轮使用同一本地操作者身份模拟，未实现角色权限或双人审批。

| 优先级 | 需求 | 状态 / 验收 |
|---|---|---|
| P0 | 案例从发现到归因、修复、回归、决策可关联 | 已实现 quality.py 与 /quality |
| P0 | 不允许凭空填写“回测通过” | 回测由固定命令生成，服务端核对案例版本和源码哈希 |
| P0 | 安全问题不能被低优先级掩盖 | safety=true 强制 P0；分类仍需人工判断 |
| P0 | 发布不绕过失败回归 | 失败、过期或跨案例回归禁止准予发布；仅记录决定，不部署 |
| P0 | 知识审批、生效、撤销 | 本文定义规则，尚未接入执行 RAG，原 FAQ 仍为 draft |
| P1 | 自动发现及聚合失败 | 当前手工登记；自动从 traces/DEAD 任务收集待实现 |
| P1 | 模型效果发布门槛 | 目前填写人工验收证据，未自动校验模型报告 |
| P1 | 可视化运营指标 | 当前案例列表与报告，未实现完整看板 |

## 2. 数据字典与治理

问题语料、知识、评测、运行记录四种数据不得混库当成同一知识来源。

每条问题规范字段：record_id、source_uri、source_revision、license、language、synthetic、intent、scenario、risk、raw_hash、normalized_hash、template_group、pii_status、review_status、split、annotator、label_reason、created_at。现有导入脚本只覆盖其中部分，不能宣称已完整实现。

处理顺序：来源许可核查 → 保留原始快照 → 联系方式/标识符隔离或占位替换 → 精确去重 → 模板近重复分组 → 人工标签审核 → 按组划分开发与评测 → 固定版本及哈希。

现有 4070 条为英文公开合成问题，不能代表中文真实工单分布。27 类草稿不是 27 类自动执行能力。新增中文案例需单独标注 synthetic=true，不能冒充真实访谈。

标注任务：先判断业务主题，再判断 ready/clarify/paused，最后标出证据消息与原文片段；执行授权另由规则核对。不强行把撤回归为 unknown。多意图、条件未满足、上下文不足需单独覆盖。争议交由第二位审阅者仲裁；当前无人独立复核，应保留 needs_review。

数据集分层：开发集用于分析和修改；固定回归集用于持续防回退（并非盲测）；保留集只在版本冻结后评估。保留集错题一旦进入开发，需更换新的保留集。不得删除错题追分。

保留策略：本机仅合成或公开许可数据；真实客户数据接入前必须定义最小采集、访问权限、删除期限和脱敏策略。现阶段不接收真实工单。

## 3. FAQ 产品规则

字段：faq_id、version、canonical_question、paraphrases、intent、required_slots、answer、policy_refs、tenant、channel、language、effective_from、effective_until、owner、reviewer、status、change_reason。

生命周期：DRAFT → IN_REVIEW → APPROVED → PUBLISHED → RETIRED。拒绝后返回新草稿版本；已发布内容不原地覆盖。回滚是重新选择仍有效的已审批版本，不恢复已失效政策。

发布验收：答案有明确适用政策；金额、时效、运费等无依据则不承诺；区分政策问答与个人订单状态查询；无可用知识时追问或转人工。退款/换货 FAQ 不生成财务授权。现有 27 类全部仍是草稿，尚未实现以上审批工作台。

示例：“退款多久到账”需要适用政策；“我的退款到了吗”需要订单身份和退款流水工具。没有实时查询工具时必须说明无法确认，禁止用通用 FAQ 冒充状态查询。

## 4. RAG 设计与实验协议

知识单位优先按完整政策条款切分，保留标题、适用条件、例外、版本与来源；不能把“允许退款”和限制条件切开。初始片段长度作为实验变量，而不是直接认定最优。当前实际语料是短合成政策，尚无长文解析器。

检索前过滤租户、审批状态、生效区间；当前代码只实现 active/tenant。当前 top-k=3、中文双字词法基线；尚未实现 embedding、混合检索或 rerank。

上下文契约：系统安全约束 > 已核实业务事实；检索内容仅作为证据数据。知识冲突或无匹配转人工。检索命中不是可回答性的充分条件。保存 corpus_hash、查询、命中文档版本、Prompt 哈希与模型用量。

下一实验固定同一批开发案例，对照无检索 / 当前词法 / 候选改进；同模型、Prompt、温度和输入顺序策略，记录完整配置及成本。每题标注所有相关片段，统计 Recall@k、MRR、无答案错误召回率；人工审核回答忠实性、正确拒答、引用支撑。任务办结率另算，不用召回率替代。现有 tiny corpus 结果不证明增益。

发布硬门槛：未授权执行、跨商家知识泄漏和过期政策放行任一失败即阻断。效果门槛先测基线、再预注册，不伪造 95% 目标或实际达成。调用真实模型需要另设预算，质量工作台默认不调用模型。

## 5. 闭环责任与状态

NEW：登记预期、实际、来源及任务/报告引用，不把“转人工”直接判为失败。
TRIAGED：选择 data/knowledge/retrieval/prompt/tool/authorization/ux，记录证据、负责人和优先级。
FIXED：记录变更引用、因果假设及本案例验证方式。系统不替代工程师修改对应模块。
回测：固定 unittest 模块清单，只执行零费用工程测试；报告保存源码指纹、套件指纹、案例版本、退出码、时间和输出哈希。
RELEASE_RECORDED / ROLLBACK_RECORDED：必须关联当前案例版本的回测和人工验收证据。准予发布还要求通过且源码未变化。此记录不修改部署、不切换 Prompt，也不代表通过模型评测。

优先级：P0=安全/越权/数据串用/重复资金动作；P1=主流程无法完成、主要场景效果回退；P2=不影响正确处理的文案或效率问题。负责人和修复时间由实际团队确定，不虚构 SLA。

根因选择指南：证据不存在→知识；证据存在但没检到→检索；已提供正确证据仍理解错误→Prompt/模型；正确方案执行错误→工具；旧意愿仍获许可→授权；标签本身有争议→数据。可在 rationale 记录次要根因。

## 6. 指标与埋点口径

公共字段：event_id、task_id、message_version、case_id（可空）、timestamp、environment、model/prompt/corpus_version、latency_ms。禁止记录密钥；不记录内部推理过程。

| 指标 | 分子 / 分母 | 注意 |
|---|---|---|
| 正确办结率 | 经独立审核正确完成任务 / 纳入评估任务 | 尚无独立业务审核，暂不报值 |
| 误执行率 | 发生越权或错误效果的任务 / 有业务效果的任务 | 另报总数；零分母为 NA |
| 澄清恢复率 | 回复后完成目标的任务 / 已收到有效澄清回复任务 | 未回复与等待中单列 |
| 转人工率 | 转人工任务 / 已结束自动处理阶段任务 | 转人工不必然是错误 |
| 回归通过率 | 通过检查 / 执行检查 | 不等于模型或业务准确率 |
| 每办结任务用量 | 模型总 tokens / 正确办结任务 | 无账单不推算实际费用 |

现有 trace 与 quality_events 为原始审计记录，尚未完成上述所有聚合。计划补 retrieval.completed、guardrail.blocked、tool.reconciled、task.closed 的统一契约；不得因文档列出就声称全部埋点上线。

## 7. 本机操作

启动：`python server.py --desktop --async-jobs --port 8769 --db data/quality-demo.db`
进入 `/quality`，登记、归因、修复后，在后端目录运行：
`python quality.py --db data/quality-demo.quality.db --case <案例ID>`
网页刷新，使用回测 ID 记录决定。不要把示例路径误用为其他服务的数据库。

接口均继承本机鉴权：GET /api/workflow/quality；POST /api/workflow/quality/cases；POST /api/workflow/quality/cases/{id}。并发编辑携带 revision，过期返回409；非法输入400；没有鉴权401。回测仅本机 CLI，不通过HTTP执行用户提供命令。

局限：事件记录不是防篡改日志；同一操作者可自审；人工验收文本真实性无法自动验证；套件成员固定但源码指纹随版本变化，历史结果不能跨版本复用；当前没有自动线上回滚。
