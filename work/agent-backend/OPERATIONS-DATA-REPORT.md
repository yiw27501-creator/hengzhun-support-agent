## 产品上学到了什么

1. 单报67%自动化会掩盖5个错误标记。看板同时展示62%的保守代理指标，但不能将其命名为“真实正确自动解决率”。
2. 回执核验83%与closed67%不是冲突：核验结果并不必然等于业务关闭。需要以后记录核验对象和结论，不能只有布尔值。
3. 超时场景全部人工，值得研究能否用回执查询减少介入；但没有逐事件日志，不能断言当前系统真的没做对账。
4. 改地址不属于当前主要执行MVP。该类用于运营覆盖分析，不因为输入里有这个标签就假装已支持。
5. 记录中的reship指补发，不自动映射为现有replace换货。输入退款金额也可能超出当前沙箱自动上限，不应直接回放执行。
6. 数据缺少客户原话、授权版本、政策版本、tool_request_id、request/receipt关系、模型与Prompt、tokens、各阶段时间。因此不能当意图识别真值、FAQ政策、RAG召回评测集或全链路压测结果。

## 接口、启动和更新

新增 `/operations` 运营页面，服务台侧栏有“模拟运营分析”。

- GET `/api/workflow/operations`：最新单一快照及分组指标。
- GET `/api/workflow/operations/{sha256}`：指定版本，避免多快照混算。
- POST `/api/workflow/operations/register-errors`：body含dataset_id，幂等登记待复核案例。
- 导入只开放本地CLI，不开放任意路径的HTTP读取。

```powershell
python operations.py --source data/operations-source/user-20260917.txt --db data/operations-demo.operations.db --quality-db data/operations-demo.quality.db
python server.py --desktop --async-jobs --port 8776 --db data/operations-demo.db
```

打开 `http://127.0.0.1:8776/operations`。此演示实例不启用付费模型；已有8775真实模型演练服务不因导入而改变。若希望并入其他实例，用其数据库前缀导入，并明确重启对应后端加载路由。
