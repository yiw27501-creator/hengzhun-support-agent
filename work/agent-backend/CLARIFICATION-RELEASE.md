# 澄清回复闭环 · 2026-09-16

已实现：理解结果需要澄清时，在当前订单和消息版本下创建 OPEN 问题；客户 reply_to 绑定问题 ID，回复与状态更新同事务保存；下一次模型上下文按顺序包含客户消息、客服追问、客户回复。继续原任务，不另建订单。

旧版本问题或跨订单回复返回冲突；普通新消息使旧问题 SUPERSEDED，回复绑定的问题为 ANSWERED；重复提交按内容、版本和问题绑定幂等。人工授权后待回答问题失效。模型追问不会自动产生财务授权。

验证：60 项后端自动化测试通过，前端语法检查通过。新增真实 HTTP 澄清冒烟测试通过，使用两次官方模型调用：模糊需求 → 追问入库 → 回复绑定 → 识别退款诉求 → 人工确认 → 规则沙箱退款。证据为 evidence/clarification-http-smoke.json（开发目录原件 data/order-understanding-smoke-1789544760078720500.json）。

页面默认无付费模型：未配置模型时不会凭空生成真实模型追问。独立重跑真实验证：
`python smoke_order_understanding.py --live --clarification`
需要本机配置官方密钥，每次最多两次理解调用，最终执行明确为规则规划器。

边界：只在本机界面展示追问，不向真实客户发送消息；客户身份仍由本机操作者模拟。语义与问法质量未经过独立业务标注，不能宣称生产可用。已有模型效果回退和标签歧义完整保留。
