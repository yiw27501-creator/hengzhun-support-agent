# 原始对话与 RAG 数据治理迭代（2026-09-15）

## 本轮交付与边界

- `conversation.py`：原始多轮消息 → 当前意图、逐字证据、澄清问题；官方模型调用，结构及证据校验，记录用量、耗时、Prompt 哈希。
- 提取结果始终 `execution_authorized=false`。模型提取不是经过验证的客户授权；不能直接写入执行层 `confirmed_intent`。后续需把消息身份、时间/版本和明确确认绑定后再放行。
- 这是可运行的 Python 模块及实验入口，尚未接入网页表单或云端服务；本轮没有修改线上站点。
- 逐字证据校验只证明引用存在，不证明意图正确或引用是最新有效诉求。此限制已写入单元测试。

## RAG 样本少：处理方法

必须区分知识覆盖不足与评测问题不足。改写同一政策生成一百问，只扩充表达覆盖，不增加业务知识。

1. **执行知识**：目前仍为 5 条有效沙箱政策，另有过期/跨租户干扰文档。本轮未虚构新增商家规则。后续按退款、换货、履约、授权、异常恢复建立缺口表，由规则负责人明确适用条件。
2. **公开参考**：`research_sources.json` 记录京东自营帮助页和市场监管总局法规页面的来源、适用范围、版本不确定性和核对范围。仅研究使用，不被执行检索器加载；不把其他商家的承诺当作本商家授权。
3. **评测扩充**：围绕每条已批准规则设计口语、多轮反转、边界、负例、无答案问题；按场景分组划分，避免同义改写跨开发/测试集。当前切分只是初始合成基线。
4. **后续真实数据**：获得授权后采集脱敏客服原话，由业务人员双人标注并仲裁；记录来源、标注者、版本和政策证据。没有业务人员时明确标注“合成 POC”，不冒充业务验证。
5. **上线门槛**：政策至少具备 tenant、来源、版本、生效/失效时间、审批状态；公开资料须经过适用性审核才能变为商家执行规则。

## 接下来优先级

- P0：证据绑定的需求澄清与确认流程接入网页；模型输出与执行授权隔离；改口使旧确认失效。
- P0：无答案、证据不充分时拒答或澄清；不能仅凭非空检索结果执行。
- P1：完成政策版本/来源/审批管理与冲突处理；公开参考不参与执行索引。
- P1：固定开发配置后运行保留测试，不按测试结果反复调参；失败进入下一版开发集，另建保留集。
- P1：同一模型、Prompt 和案例下比较无检索/现有检索/改进检索，记录正确性、证据支持率、成本和延迟。本轮尚未完成消融，不能宣称 RAG 有提升。

## 复现

python evaluate_dialogue.py --live --direct --split dev
python evaluate_retrieval.py --split dev
