# 知识治理与质量准入 · 2026-09-16

## 本轮实现

- /knowledge：政策与 FAQ 创建不可变正文版本，草稿→审核→批准→发布→撤销；拒绝回草稿，新正文需建新版本。
- 发布要求当前有效；同 ID 新版发布原子撤下旧版；租户隔离；FAQ 必须引用当前生效政策版本。政策过期或撤销后引用它的 FAQ 不再出现在 /api/workflow/faq/published。
- 可手动导入现有合成政策与公开语料 FAQ 为草稿，绝不自动批准。缺少政策依据的 FAQ 不能发布；不要编造政策来通过审核。
- 异步真实模型运行时使用对应 .knowledge.db 的已发布政策，每次检索重新读取。空库不回退到未审核政策，而是转人工。独立历史评测仍使用 policies.json 固定基线，不与新运行时混报。
- worker 自动收集 planner.failed、guardrail.blocked 和两类队列 DEAD，以来源键去重。它们进入 NEW 待归因，不将所有拦截当作错误，不复制原始敏感消息。
- 模型类变更（prompt/retrieval/knowledge/data）需在 TRIAGED 阶段冻结评测 ID、预期标签、安全样本，再登记修复并导入完整基线/候选逐条结果。服务端重算，候选不得低于基线且安全样本全通过。
- 批准发布必须同时关联同案例同版本的工程回测和通过的模型评测；源码变化使旧准入失效。回退仍可记录，不自动执行部署。
- 新本机视觉：共享 console.css，浅灰/白/低饱和绿，统一导航、可折叠技术细节、知识管理双栏及窄屏单栏。

## 可复现验证

`python -m unittest discover -q`

`python server.py --desktop --async-jobs --port 8770 --db data/governance-demo.db`

浏览 /lab、/knowledge、/quality。默认没有付费模型。此前已启动的服务不会自动加载 Python 修改，请使用新端口或明确重启对应进程。

模型报告导入格式：baseline 与 candidate 均为数组，每条包含 id、prediction、response_id、model、prompt_hash。预期答案由冻结协议提供；不接受客户端的 correct 或 passed 字段。当前支持离散标签一致性，不是开放式回答质量评测，也没有自动拉取供应商签名记录。

## 仍需诚实说明

本地操作者可自审；未做 RBAC/双人审批/防篡改。模型报告为操作员导入，系统校验完整性和门槛，但不能证明 response_id 真伪；本轮无新增付费调用，不宣称模型效果提升。发布为本地知识发布或产品决策记录，不是云端部署。运行中的旧规划与政策撤销尚无跨数据库原子栅栏，工程规则继续作为财务安全兜底；需要生产级撤销即时性时必须补执行前策略版本锁。没有更新旧公开网站及旧 GitHub 导出快照。

质量自动收集覆盖明确异常和死信，不覆盖没有技术异常但语义错误的全部 Bad Case；需要人工抽检补充。数据近重复分组、中文业务标注、独立保留集仍按 QUALITY-PRODUCT-SPEC 执行，未因新增工作台自动完成。
