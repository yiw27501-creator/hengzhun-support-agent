# 衡准 · 售后服务工作台

新业务界面项目，复用相邻 agent-backend 的完整 Agent 能力。不是第二套假数据前端；不删除旧产品入口、客户视角、实验台、知识治理和质量运营。

## 运行

在相邻 agent-backend 中执行：

`python server.py --desktop --async-jobs --port 8772 --db data/business-demo.db --dialogue-router split`

访问 http://127.0.0.1:8772/service 。Python 标准库，无前端构建依赖。此目录单独打开 HTML 不可工作，必须与后端一同发布。

## 业务交互

1. 客服进入即看到工单收件箱、自动完成数、待人工处理数。
2. 点击“开始自动处理”创建 6/30/60 单，后台实际运行原有规则引擎和持久化队列。
3. 换货、退款、回执丢失恢复可自动办结；客户改口、身份和库存不明转人工。
4. 客服查看客户原话、订单事实和业务时间线。客户改口需先取得新回复，再核对意愿交回处理。
5. 身份未验证和库存失效不会因人工确认就自动放行。没有实现真实身份/库存补录工具，保留待核对。

## 指标与数据边界

- 统计范围：当前数据库所有 business_tickets，非全项目历史任务，也不限定当天。
- 自动办结：COMPLETED 且没有人工确认标记；不是独立业务正确率。
- 自动办结占比：自动办结 / 全部业务演练工单，包含等待中的工单，随处理进度变化。
- 平均耗时：已完成工单从创建到最新核验事件的平均时间，包含排队与人工等待，不是模型推理延迟或人力节省。
- 六类场景均衡配比为人为设计；结果不能用来推断真实自动化率。
- 本轮中文订单为项目编写的合成场景，未将 Bitext 外部问题直接转换成执行授权。原 4070 条语料、FAQ 草稿和评测能力仍在原模块保留。
- 批量功能拒绝真实模型模式，避免无预算费用；页面回复为状态摘要，不冒充 LLM 生成或客服渠道发送。
- 单批请求 ID 幂等；中断后使用同一 ID 重试补投队列。单数据库最多600演练工单；未自动定时修复未投递批次。

## 安全与发布

同一本机操作者，不是生产 RBAC。不得暴露开发服务器或录入真实客户数据。当前没有真实商家/支付/渠道接入，没有声称降本收益。

GitHub 后续需要一并打包本目录与更新后的 agent-backend，排除 .env、数据库、完整运行日志与旧凭据。旧 github-ready 副本尚未同步本轮代码。未自动上传或部署。
