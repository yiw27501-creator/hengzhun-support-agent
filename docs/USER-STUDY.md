# 售后工作台小规模使用测试方案

状态：**待执行**。本文件是研究方案与记录模板，不包含真实参与者、观察结果或效果结论。

## 目的与参与者

邀请 3–5 位做过电商售后的客服或运营人员，观察他们能否在无操作提示的情况下辨别事实、授权和执行结果。记录其角色、售后经验和所用设备；不要把小样本推算为行业自动化率。

演示只使用全新本机沙箱数据库和合成订单。不要录入真实客户姓名、订单号、地址或支付资料。开始前告知参与者这是产品原型，允许随时停止，并征得是否记录屏幕及匿名引语的同意。

## 固定任务

主持人只读出任务目标，不指出按钮位置。每位参与者使用相同任务顺序；每个任务从全新演示数据开始，避免前一任务影响状态。

| 任务 | 给参与者的目标 | 应观察到的关键判断 |
| --- | --- | --- |
| A 缺货 | 找到一笔缺货工单，确认客户的当前选择并核对处理结果 | 区分库存查询、客户确认和最终回执 |
| B 改口 | 客户先说换货，随后说“先别处理”；请继续处理 | 旧同意是否被视为失效，是否误点执行 |
| C 回执丢失 | 工具显示超时；判断是否需要再次执行 | 是否先查已有回执，避免重复操作 |
| D 已签收退货 | 客户要退货退款；推进到合法的最终状态 | 是否区分寄回、仓库签收、验收与退款 |

## 记录口径

每个任务从主持人读完目标计时，到参与者明确宣布完成或放弃结束。记录：是否独立完成、用时、求助次数、关键误操作、口述理由和卡点。只有观察到对应回执并确认业务状态，才记为“完成”；页面显示“队列完成”不自动算业务完成。

关键误操作包括：无当前授权却尝试执行、身份未核实而放行、仓库未验收就退款、超时后直接重做有副作用动作。误点如果被系统拦截，分别记录“用户尝试”和“系统拦截”，不要混成一次已发生资金错误。

## 复盘与发布条件

逐条回看关键误操作，先区分界面理解问题、流程规则缺口、系统错误和演示环境故障。把每个拟修改点与原始观察、假设、改动及复测结果相连。若出现任何未被系统拦截的关键误操作，先冻结自动财务路径并修复；即便没有观察到错误，也不能据此证明生产安全。

对外报告只写实际参与人数、任务完成情况和观察到的案例。未招募或未执行时保持“待执行”，不填写预设百分比或节省工时。
