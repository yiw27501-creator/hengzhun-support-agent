# 固定工作流评测与证据边界

## 可复现的工程基线

`work/agent-backend/workflow_eval_cases.json` 冻结了 9 个项目编写的合成场景与预期结果。运行：

```powershell
cd work/agent-backend
python evaluate_workflow_baseline.py
```

脚本在临时数据库启动本机 HTTP 服务和持久化队列，使用规则规划器以及确定性的模型路由替身；它会走工单 API、状态转换、沙箱执行与回执查询。结果写入 [基线报告](../work/agent-backend/evidence/workflow-baseline.json)。失败时退出码为 1，适合 CI 回归。不会调用付费模型、商家系统或支付接口。

| 检查范围 | 固定案例 |
| --- | --- |
| 授权失效与模型边界 | 执行前撤回、非法模型动作不得执行 |
| 自动路径与幂等 | 换货、退款、响应丢失后的对账和单一回执 |
| 等待与人工协作 | 改口后只查信息、身份两步核对、库存更新后重新确认 |
| 退货长流程 | 仓库验收前无退款，验收后才允许沙箱退款 |

这 9 项是**工程回归覆盖数**，不是真实模型准确率、独立专家判定、商家自动解决率或降本证明。模型替身按关键词返回固定动作，不能拿它评价 DeepSeek 的识别能力。历史真实模型实验见 [模型桥接说明](../work/agent-backend/BUSINESS-MODEL-BRIDGE.md)，其样本、政策与版本不能和本基线合并计算一个总分。

## 下一轮模型评测的冻结规则

在调用模型前保存并审阅案例、预期标签、适用政策版本及判分脚本。至少覆盖：条件性退款、客户撤回、代买身份、库存过期、工具超时、无答案政策和来源文本中的指令干扰。分别统计意图理解、对话状态、证据引用、工具选择、执行许可与最终回执，不用单个“正确率”掩盖危险错误。

保留开发集与未参与调参的测试集，记录模型名、提示词哈希、请求 ID、token、费用或预算、延迟、失败原因及人工复核意见。任何提示词、政策或工具契约变更都用同一冻结集回归；需要新增案例时另记版本和原因。模拟案例始终标注来源，不得冒充真实客服对话。

## 用户价值验证

真人使用测试按 [研究方案](USER-STUDY.md) 执行。只有获得真实商家授权并有可比较的人工基线后，才能讨论节省时长或 ROI；当前附带的 100 条运营记录只是手工编写的模拟数据。
